KEY ANSWERS TO YOUR QUESTIONS
================================================================================

1. HOW DOES THE APP HANDLE NAVIGATION TO THE ORDERS PAGE WITH PARAMETERS?

   ANSWER: The app does NOT use GoRouter parameters for orders.
   
   - Route Definition: Simple /orders path (no parameters)
   - Navigation Method: Direct context.go('/orders')
   - Order Data Passing: Full Order objects passed via Material Navigator
   
   File: /lib/core/router/app_router.dart (Lines 112-115)

2. IS THERE A MECHANISM TO SCROLL TO OR HIGHLIGHT A SPECIFIC ORDER?

   ANSWER: No built-in mechanism exists.
   
   - Scroll Controllers exist but are not used for targeting
   - PageStorageKey preserves position but doesn't jump to order
   - Could be implemented using route parameters (not currently done)
   
   Infrastructure Available: ScrollController + PageStorageKey
   File: /lib/features/orders/presentation/pages/orders_page.dart (Lines 30-31, 233-234)

3. WHAT NAVIGATION PATTERNS ARE USED?

   ANSWER: Mixed approach - GoRouter for main routes, Material Navigator for complex objects
   
   Patterns Used:
   a) GoRouter direct:     context.go('/orders')
   b) Router extension:    ref.read(appRouterProvider).goToOrders()
   c) Material Navigator:  Navigator.push(MaterialPageRoute(builder: ...))
   d) Path parameters:     /menu/items/:id/edit (menu only, not orders)
   
   Files: /lib/core/router/app_router.dart (extension at line 171)

4. HOW ARE ORDER IDS OR ORDER NUMBERS PASSED?

   ANSWER: Full Order objects passed via constructor parameters
   
   Current Flow:
   Orders Page → User clicks Edit → _navigateToOrderDetail(order)
   → Navigator.push(MaterialPageRoute(builder: (context) => PosPage(existingOrder: order)))
   → PosPage receives order via widget.existingOrder property
   
   Not via URL/route parameters, but via widget constructor
   
   File: /lib/features/orders/presentation/pages/orders_page.dart (Lines 774-785)

NAVIGATION ARCHITECTURE OVERVIEW
================================================================================

ROUTER STRUCTURE:
  ShellRoute (MainLayout wrapper)
    ├─ /dashboard
    ├─ /menu (with nested routes)
    ├─ /orders ← Simple route, no parameters
    ├─ /pos
    ├─ /analytics
    ├─ /finance
    └─ /settings

NAVIGATION FLOW (Dashboard → Orders → Edit):
  1. Dashboard "View All" → context.go('/orders')
  2. OrdersPage loads and fetches orders list
  3. User clicks "Edit" button on order card
  4. _navigateToOrderDetail(order) called
  5. Navigator.push with PosPage(existingOrder: order)
  6. PosPage receives full Order object
  7. _loadExistingOrder() converts to cart format
  8. User edits and saves
  9. PosPage pops with true result
  10. OrdersPage catches result and _loadOrders(false)
  11. UI updates with fresh data

================================================================================
CURRENT LIMITATIONS
================================================================================

1. Cannot navigate to orders page with specific order ID via URL
   Limitation: Route has no :id parameter
   Impact: Can't deep link to specific order
   
2. No built-in scroll-to-order functionality
   Limitation: Scroll controllers exist but not used programmatically
   Impact: Large order lists don't auto-scroll to target order
   
3. No visual highlight for recently edited order
   Limitation: Orders reload but no animation to highlight changes
   Impact: Users must manually find edited order
   
4. Orders passed as full objects, not IDs
   Limitation: Complete Order serialization in memory
   Impact: Large order objects consume memory
   
5. No query parameters support
   Limitation: GoRouter not used for orders navigation
   Impact: Can't filter/sort via URL

================================================================================
PATTERN SUMMARY
================================================================================

MAIN PATTERN: Material Navigator + Constructor Parameters
  Location: OrdersPage → PosPage
  Method: Navigator.push(MaterialPageRoute(builder: (context) => PosPage(order)))
  Advantage: Can pass complex objects
  Disadvantage: No URL state preservation

SECONDARY PATTERN: GoRouter for main routes
  Location: Dashboard → OrdersPage
  Method: context.go('/orders')
  Advantage: Clean, type-safe
  Disadvantage: No parameters supported

DATA REFRESH PATTERN: Return value checking
  Location: Post-navigation .then() callback
  Method: Check if result == true, then _loadOrders()
  Advantage: Only reloads when necessary
  Disadvantage: Manual coordination needed

SCROLL PRESERVATION PATTERN: PageStorageKey
  Location: ListView in OrdersPage
  Method: key: const PageStorageKey('active_orders_list')
  Advantage: Automatic scroll position saving
  Disadvantage: Not used for jumping to specific item

CODE EXAMPLES
================================================================================

NAVIGATE TO ORDERS:
  context.go('/orders');

NAVIGATE TO EDIT ORDER:
  Navigator.of(context).push(
    MaterialPageRoute(
      builder: (context) => PosPage(existingOrder: order),
    ),
  ).then((result) {
    if (result == true) {
      _loadOrders(showLoading: false);
    }
  });

LOAD EXISTING ORDER IN POS:
  if (widget.existingOrder != null) {
    _loadExistingOrder(widget.existingOrder!);
    _showEditingTransition();
  }

ACCESS ORDER DATA IN POS:
  final orderId = widget.existingOrder?.id;
  final orderNumber = widget.existingOrder?.orderNumber;
  final items = widget.existingOrder?.items;
